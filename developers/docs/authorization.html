Authorize, capture, reverse, refund. Partial approvals, stand-in when the issuer is slow, and the score that rides on every answer.

Before you startA sandbox token from the quickstart. The Authorization object in the reference.

Authorize

An authorization asks the issuer to hold an amount. The answer is a decision, the issuer's code, and how long the issuer took. Answered within 500 ms, or by stand-in rules you set.

curl -X POST https://sandbox.api.dgn.com/acceptance/v1/authorizations \
  -H "Authorization: Bearer $TOKEN" -H "Idempotency-Key: $(uuidgen)" \
  -d '{ "amount": 5820, "currency": "USD", "merchant_id": "mch_demo", "pan_token": "tok_9d1b4e", "entry_mode": "ecommerce", "avs": { "street": "12 Ash St", "postal": "80202" } }'
const auth = await dgn.authorizations.create({ amount: 5820, currency: "USD", merchantId: "mch_demo", panToken: "tok_9d1b4e", entryMode: "ecommerce", avs: { street: "12 Ash St", postal: "80202" } });
auth = client.authorizations.create(amount=5820, currency="USD", merchant_id="mch_demo", pan_token="tok_9d1b4e", entry_mode="ecommerce", avs={"street": "12 Ash St", "postal": "80202"})

Partial approval

A prepaid or limited card may approve less than requested: decision: partial, code 10, and approved_amount. Capture that amount, or reverse and ask for another card.

Stand-in

When the issuer does not answer in time, the network answers on your stand-in rules: a ceiling per transaction and per card per day, set in Configuration. The response carries answered_by: network. Stand-in approvals clear like any other.

Capture

Move an approved hold into the day's clearing file. Within 7 days, in full or in part. A batch takes up to 5,000 ids on one call.

curl -X POST https://sandbox.api.dgn.com/acceptance/v1/captures \
  -H "Authorization: Bearer $TOKEN" -H "Idempotency-Key: $(uuidgen)" \
  -d '{ "authorization_id": "auth_71ab3c", "amount": 5820 }'
await dgn.captures.create({ authorizationId: "auth_71ab3c", amount: 5820 });
// end of day
await dgn.captures.createBatch({ authorizationIds: ids });
client.captures.create(authorization_id="auth_71ab3c", amount=5820)
client.captures.create_batch(authorization_ids=ids)

Reverse

Release a hold you no longer need, in full or in part. The issuer sees it immediately. A reversal after capture is a refund.

curl -X POST https://sandbox.api.dgn.com/acceptance/v1/authorizations/auth_71ab3c/reverse \
  -H "Authorization: Bearer $TOKEN" -H "Idempotency-Key: $(uuidgen)" \
  -d '{ "amount": 5820 }'
await dgn.authorizations.reverse("auth_71ab3c", { amount: 5820 });
client.authorizations.reverse("auth_71ab3c", amount=5820)

Refund

Return captured money to the cardholder. Full or partial. Reaches the cardholder in 3 to 5 days and appears in that night's cycle as an adjustment.

curl -X POST https://sandbox.api.dgn.com/acceptance/v1/refunds \
  -H "Authorization: Bearer $TOKEN" -H "Idempotency-Key: $(uuidgen)" \
  -d '{ "authorization_id": "auth_71ab3c", "amount": 2000, "reason": "requested_by_customer" }'
await dgn.refunds.create({ authorizationId: "auth_71ab3c", amount: 2000, reason: "requested_by_customer" });
client.refunds.create(authorization_id="auth_71ab3c", amount=2000, reason="requested_by_customer")

The score

Every authorization response carries score, 0 to 100, and score_reasons: network-side signal the issuer does not hold, such as whether this device has paid this merchant before. Read it or ignore it. Rules on it live in Fraud in the Partner Portal.

If your platform speaks ISO 8583

The mapping is direct. DE 4 is amount, DE 49 is currency, DE 22 is entry_mode, DE 39 comes back as response_code. The ISO 8583 bridge sample maps a 1987-variant message field by field.
